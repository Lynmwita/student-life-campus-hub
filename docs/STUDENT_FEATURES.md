# Student pilot features

`/campus-life` provides campus events, synced UAMS events and exam/term/deadline dates in a month-filtered calendar with `.ics` export. Local event RSVPs and club joins persist per authenticated student. Event check-in is server validated and appears in the next reverse sync. Imported events and academic dates remain governed by their source system.

`/feedback` accepts a rating, category and free text from a verified account. Staff review feedback from the admin Feedback tab; students see their status and response. The reverse integration transfers these records to UAMS. Demo accounts never persist feedback or push subscriptions.

Profile has opt-in browser notification settings with P1–P4 selection. Configure `NEXT_PUBLIC_VAPID_PUBLIC_KEY`, server-only `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` (a mailto or HTTPS contact), and `SUPABASE_SERVICE_ROLE_KEY`. Generate a matching VAPID pair with the web-push CLI and store the private key only in deployment secrets. Local publication and successful UAMS imports trigger delivery. Recipients must have a verified matching membership and selected the notice priority. Transport urgency is high/normal/low/very-low. Notification previews contain a generic notice message, never personal notice content. Expired endpoints are removed; transient failures retry on the next import. Local publication errors are logged and can be retried by invoking the same server delivery helper with the persisted notice ID. Real push delivery requires HTTPS, browser permission, the migrated database and deployment secrets; tests mock the external push service.

Profile also provides opt-in saved core views for personal devices. These are JSON snapshots of viewed notices/timetable/campus data, scoped by the current account and browser session, expire after 24 hours, and are cleared on sign out/account switch. Login clears saved data. This is device storage, not encryption: avoid enabling it on shared devices. The static offline fallback can display saved data while disconnected. Mutations require a connection. The service worker caches only public build assets/icons/offline fallback; it never caches authenticated HTML, RSC or API responses. Activation removes older shared page caches. Low data mode hides optional media.

Apply both `hub_feedback_push` and `uams_academic_records` migrations before enabling these features. The first grants narrowly scoped access and RLS for feedback, push subscriptions, delivery receipts, RSVPs and club joins. Run the PGlite database tests and service worker/offline privacy tests before release. Actual browser permission/push delivery and multi-device behavior still need validation in a configured staging deployment.
